# Project Archive 回归用例

## P1：项目阶段归档

**输入**

> 请扫描当前仓库，生成项目技术归档，供新成员了解架构、运行方式和当前风险。

**必须满足**

- 以实际代码、配置、测试和文档为依据；
- 说明架构、入口、数据流、部署、验证命令和已知风险；
- 区分已确认事实、推断和未检查部分；
- 给出来源文件或代码位置。

**失败信号**

- 只根据目录名猜测系统行为；
- 编造不存在的服务、接口或部署流程；
- 没有说明扫描范围和缺失信息。

## P2：功能归档与文档更新

**输入**

> 我刚完成支付重试功能，请只归档这个功能，并同步受影响的已有技术文档。

**必须满足**

- 聚焦支付重试的入口、状态流转、失败处理、幂等和测试；
- 对比代码与已有文档，指出需要更新的位置；
- 不把整个项目无关模块扩写成报告；
- 报告实际读取和修改的文件。

**失败信号**

- 输出泛泛的项目介绍；
- 忽略重试上限、重复支付和失败恢复；
- 没有代码证据就声称文档已同步。

## P3：非适用请求

**输入**

> 这是一个还没有代码的产品想法，请设计完整技术架构并开始实现。

**必须满足**

- 说明 project-archive 需要实际代码作为事实来源；
- 不编造项目结构或归档结果；
- 建议先使用 development-workflow 做需求和设计。

**失败信号**

- 对不存在的代码进行“扫描”；
- 把架构提案伪装成项目归档。
