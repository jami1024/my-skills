# FastAPI API 边界决策

仅在当前改动涉及这些边界时读取。先核对项目现有版本、客户端契约、认证和存储方案，不因参考示例迁移依赖。

## 认证与授权

- 先复用项目已有认证方式；认证确认身份，授权检查资源归属及操作权限。
- JWT、服务端 session 和签名 Cookie 的选择取决于客户端、撤销要求、存储和部署约束，不能仅凭“REST API”或“微服务”决定。
- 令牌验证复用已采用库的完整校验流程，检查签名、允许的算法、有效期及项目要求的签发者、受众和 subject；无效凭据映射为稳定的认证错误。
- 区分仅签名的客户端 Cookie 与服务端 session 存储；不要把启用 session middleware 描述为自动接入 Redis。
- Cookie 的 Secure、HttpOnly、SameSite 和 CSRF 策略按实际登录与跨站流程设计；登出、轮换及撤销语义写入契约。
- 不把密码、令牌、内部错误或不必要的用户信息写入响应和日志。

## API 版本

沿用现有路径、请求头或其他版本约定。没有兼容性需求时，不为了示例同时创建 v1/v2。

```python
# 项目已采用 URL 版本时，按既有路由注册方式扩展。
app.include_router(v1_router, prefix="/api/v1")
```

版本变化应说明旧客户端行为、迁移与下线条件；不默默改变公开接口。

## 错误映射

- 在数据库边界区分 not-found、唯一约束、超时及其他基础设施错误，保留可诊断原因。
- 业务错误表达资源不存在、冲突或规则失败，不要求业务层依赖 HTTP 状态码。
- HTTP 边界按既有契约映射状态码、错误代码和安全的提示；不直接返回 SQL、异常类名、完整堆栈或敏感字段。
- 为相关成功、失败及边界行为补充测试，不为统一格式重写全部端点。

## 文件上传

先确认大小限制、允许类型、权限、保存位置和清理策略，再选择读取方式。

- 只有明确受限的小文件才整段读入内存；大文件分块处理，并累计检查实际大小。
- 文件名、扩展名和客户端 Content-Type 都是不可信输入；保存键由服务端生成，不把原始文件名直接拼接到磁盘路径。
- 存储位置不应允许上传文件被直接执行；失败或取消后清理部分文件，并避免覆盖已有对象。
- 异步端点使用异步客户端；同步存储 SDK 的调用按项目已有方式卸载到线程等执行环境，不直接阻塞事件循环。
- 需要预签名上传时，明确对象键、权限、有效期、大小校验和完成确认。

## 验证

按当前变更选择：未认证与无权限、无效或过期凭据、资源冲突、上传超限、非法文件名、存储失败和取消恢复。记录实际执行的命令及未覆盖项。
