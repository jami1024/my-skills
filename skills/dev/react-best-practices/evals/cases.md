# React Skill 回归用例

## R1：新项目架构推荐

**输入**

> 我要做一个面向公众的内容管理 Web 应用，团队熟悉 React 和 TypeScript，需要 SEO、权限、后台表单和端到端测试。请推荐 React 技术栈和项目架构。

**必须满足**

- 先分析 SSR/SEO、权限、表单和测试需求；
- 比较至少两种合理方案，并说明取舍；
- 给出目录结构、路由、数据获取和状态边界；
- 给出验证命令和后续初始化步骤；
- 不直接运行或假设某个固定脚手架。

**失败信号**

- 直接安装 Vite、Zustand、TanStack Query 或 shadcn/ui；
- 只输出一套技术名，没有选择理由；
- 忽略 SEO、权限或 E2E 测试。

## R2：已有 Vite 项目适配

**输入**

> 这个项目已经使用 Vite、React Router、Redux Toolkit 和 CSS Modules。请新增用户列表页，并设计数据获取和组件结构。

**必须满足**

- 先读取并复用已有技术栈；
- 不建议迁移到 Next.js、Zustand、Tailwind 或其他 UI 库；
- 明确页面、组件、API、类型和测试边界；
- 覆盖 loading、error、empty 和分页状态。

**失败信号**

- 将 Redux Toolkit 改成 Zustand；
- 将 CSS Modules 改成 Tailwind；
- 重新搭建路由或推荐脚手架。

## R3：已有 shadcn/ui 项目

**输入**

> 项目根目录有 `components.json`，已经使用 shadcn/ui 和 Tailwind。请添加一个带校验、错误提示和提交状态的用户表单。

**必须满足**

- 读取 `components.json` 和现有组件 API；
- 复用项目的表单、Button、Input 和错误展示模式；
- 明确 schema、默认值、提交中和服务端错误；
- 只在项目需要时推荐表单库。

**失败信号**

- 使用已删除或旧版 `shadcn-ui` CLI；
- 忽略现有组件库配置；
- 只生成成功状态，没有错误和重复提交处理。

## R4：简单本地交互

**输入**

> 给设置页增加一个只在当前组件使用的展开/收起开关。

**必须满足**

- 优先使用组件本地状态；
- 不引入 Context、Zustand 或服务端数据层；
- 给出最小实现和必要测试。

**失败信号**

- 创建全局 store；
- 添加新的依赖或复杂目录层级；
- 为简单交互提出缓存、预取或状态同步方案。

## R5：性能问题定位

**输入**

> 用户列表滚动很卡，请优化这个 React 页面。

**必须满足**

- 先要求或建议使用性能工具确认瓶颈；
- 区分网络、渲染、长列表和 Bundle 问题；
- 只提出与测量结果对应的优化；
- 保持功能、可访问性和测试不回归。

**失败信号**

- 无依据地给所有组件加 `memo`；
- 直接引入虚拟列表而不确认列表规模；
- 只谈性能，不处理 loading、error 和键盘操作。

## R6：交付审查

**输入**

> 请审查这次 React 功能提交是否可以发布。

**必须满足**

- 检查 typecheck、lint、测试和 production build；
- 检查 loading、error、empty、权限和网络失败；
- 检查语义 HTML、焦点、键盘、对比度和响应式；
- 检查客户端 Bundle 是否包含密钥；
- 输出分级问题、证据和修复建议。

**失败信号**

- 只做代码风格评价；
- 没有验证命令或发布判断依据；
- 把视觉偏好当成硬性工程缺陷。
