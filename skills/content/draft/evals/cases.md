# Draft 回归用例

## C1：播客整理成公众号文章

**输入**

> 根据下面的播客文字稿整理一篇中文公众号 Markdown 文章。保留嘉宾观点，适合普通读者阅读，并在需要配图处给出图片提示词。

**必须满足**

- 输出 Markdown 文章结构，有标题、导语、正文和结尾；
- 区分主持人、嘉宾和作者整理，不编造身份；
- 保留可核验事实、原意和不确定信息；
- 图片提示词放在对应位置，但不直接生成图片。

**失败信号**

- 把播客改写成会议纪要；
- 编造时间戳、数据、嘉宾经历或收听链接；
- 输出 HTML、图片文件或无法执行的配图指令。

## C2：缺少来源信息

**输入**

> 这是一个没有作者、日期和链接的访谈文字稿，请整理成文章。

**必须满足**

- 缺失元信息明确标记为“未提供”；
- 只根据文字稿整理，不用常识补全事实；
- 对不确定表述保留限定语。

**失败信号**

- 猜测发表日期或嘉宾身份；
- 把编辑推断写成原话；
- 为了完整而伪造来源入口。

## C3：非适用请求

**输入**

> 请把这段 API 错误日志改成修复方案并直接修改代码。

**必须满足**

- 说明 draft 适合内容成稿，不替代调试或代码实现；
- 可以整理日志中的事实，但不假装完成修复；
- 建议使用系统化调试或技术栈 skill。

**失败信号**

- 把日志编成公众号文章；
- 没有复现和代码证据就给出确定根因。

## C4：语言与论证质量

**输入**

> 请把下面这段素材整理成简短中文公众号 Markdown 成稿，不生成图片。素材：某团队把日志排查从人工翻查改成脚本处理，脚本先按时间排序，再按错误码分组。团队负责人说，改动后平均定位时间从 40 分钟降到 10 分钟。该数据没有第三方复现。

**必须满足**

- 评价性表述能归属到素材出处或作者的显式判断，没有替读者定调的插入语（按功能判定，不以词表为准）；
- 段落结尾不复述本段结论；
- 数字带上转述口径，不写成普适结论；
- 段落之间的关系可指认，因果与转折有素材依据；
- 作者推演显式标记，不与素材事实混排；
- 否定对偶不超一次，没有「从……到……」式假区间和「从而」「进一步」式空尾句。

**失败信号**

- 用评价性插入语替读者定调（「值得注意」之外，「与此同时」「不难发现」「真正」「恰好」同理）；
- 把 40 分钟到 10 分钟换算成素材没给的「效率提升 75%」；
- 出现「然而」但前文没有与之冲突的事实；
- 结尾用泛泛鼓励收尾。
