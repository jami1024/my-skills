# 原版／精简版准确性核验

## 判定边界

本核验审阅既有 32 次输出（8 个场景 × 2 个版本 × 2 轮），不新增模型调用。**这不是盲评**：初次比较时已查看过其中部分答案，且原用例参与了 skill 优化设计；本文是带证据的事后审计，不能报告为总体准确率或统计显著性。

逐项判定使用 `skill-accuracy-criteria.json` 中冻结的关键断言。`pass` 表示该次回答满足断言，`fail` 表示存在直接证据反驳或必要要求未满足，`unverified` 表示当前材料/环境不足。原版错误不抵消精简版错误；格式、事实和可运行性分别判断。

所有输入、版本哈希、模型事件、原始答案、隔离夹具和追加程序结果保留在忽略目录 `.tmp/skill-version-compare/`。评估开始时生成的优化版文件哈希均未变化。主要追加验证数据在 `.tmp/skill-accuracy/verification.json`，逐次 tutorial 输出在 `tutorial-checks.json`，SQLAlchemy 和 store 反例结果可由 `verification.json` 重现。

## 机器可核实的结论

### 教程代码

从 4 份教程分别提取完整主程序和两道练习，AST 拼装练习明确的代码片段，在隔离命名空间运行，并与对应回答中声明的输出逐行比对：

| 版本／轮次 | 完整程序 | 练习 1 | 练习 2 |
| --- | --- | --- | --- |
| 原版 R1 | 通过 | 通过 | 通过 |
| 精简版 R1 | 通过 | 通过 | 通过 |
| 原版 R2 | 通过 | 通过 | 通过 |
| 精简版 R2 | 通过 | 通过 | 通过 |

4 个完整主程序也通过 Python 3.11 语法解析。**运行时实际使用 Python 3.14.3，不是 Python 3.11**；因此这证明示例在本机运行且输出匹配，不证明 Python 3.11 运行兼容性。未测试练习中未提供完整代码的所有人工步骤。

### SQLAlchemy 事务边界

临时隔离安装 SQLAlchemy 2.0.46、aiosqlite 和 greenlet，不改项目依赖。在内存 SQLite AsyncSession 上验证：

- 先执行查询会启动 autobegin；随后直接 `async with session.begin()` 抛 `InvalidRequestError: A transaction is already begun on this Session.`，不会自动复用已有事务。
- 单一 `session.begin()` 中先写用户、再注入异常，退出后用户记录为 0，说明该示例事务边界能回滚。
- 先 commit 用户、再让审计失败，结果是用户 1、审计 0，证明分别提交无法提供原子性。

这是对建议中事务语义的最小实验，不是 FastAPI 完整服务或生产数据库集成测试。SQLite 结果不能替代目标数据库验证。

### store 写入边界

在评估冻结的 `importer.py` 上分别验证：重复 email 在写入前被拒，已存在的 store 保持不变；而第二行在 `store.extend` 生成期间失败时，第一行已经写入并保留。故“重复校验失败时零写入”正确；“任何异常都整批零写入”错误。

| 完整待办教程 | 主程序与练习均执行匹配；声明未运行 | 主程序与练习均执行匹配；声明未运行 | 此样本未发现精简版准确性退化；输出仍更长，且 Python 3.11 运行未验证 |

“原版 / 精简版”各 16 次正常结束，只代表模型响应正常，**不是 16/16 正确**。断言级、轮次级证据和标准存于前述 `verification.json` 与原始 answer 文件中；没有把异质问题压缩成一个会掩盖错误的总分。

## 退化与可下结论范围

1. **两项明确的精简版关键退化**：归档 R1 将查重前校验的局部保证扩大成所有异常零写入；FastAPI R2 把 `session.begin()` 描述为可自动复用活动事务，实测相反。
2. **一项精简版计划规则未落实**：开发计划 R2 要求已存在的去重行为先“红灯”，却没有先接受当前实现可能已满足行为。
3. **两版共同的格式失败**：一句话题第二轮都输出多段。
4. **没有证据支持全部精简均有害**：教程代码在本机运行一致；演讲字段匹配变好；Go 配置边界和 FastAPI 第一轮判断基本保留。
5. **不能用 32 次推算普适准确率**：样本小、两轮、单模型、测试题已知；没有双人盲评和新题留出集。准确性无损标准本轮未通过。

据此，对当时版本的适当结论是：**精简有效降低上下文输入，但准确性保持尚未得到验证，而且已实证出现局部退化；不应宣称“准确性不下降”。**
