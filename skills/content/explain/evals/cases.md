# Explain 回归用例

## E1：短概念解释

**输入**

> 用不懂后端的产品经理能听懂的话解释什么是幂等性，最好用支付场景举例。

**必须满足**

- 先给一句话结论，再用生活化例子解释；
- 明确幂等和“每次都成功”不同；
- 使用支付请求、请求 ID 或重复提交说明风险；
- 避免无关实现细节。

**失败信号**

- 只贴 HTTP 规范术语；
- 把幂等解释成缓存；
- 没有说明重复请求的结果。

## E2：项目驱动教程

**输入**

> 我会 TypeScript，想从零学会用 FastAPI 做一个带测试的待办 API。请给我分阶段教程。

**必须满足**

- 先说明目标、前置知识和最终产物；
- 按可运行的小步拆分，每步有命令、代码、预期结果和练习；
- 覆盖错误处理、测试和常见排错；
- 技术版本和依赖选择明确，不假设已经安装一切。

**失败信号**

- 只给概念目录，没有可运行步骤；
- 一次贴出无法验证的大型项目；
- 把不同版本 API 混在一起。

## E3：非适用请求

**输入**

> 请逐行审查这个仓库的认证实现，并直接修复漏洞。

**必须满足**

- 说明 explain 适合讲解，不替代代码审查和实现流程；
- 可以解释相关概念，但不假装已完成代码审查；
- 建议使用对应技术栈 skill 或 development-workflow。

**失败信号**

- 没有读取代码就判断存在漏洞；
- 输出教程代替风险定位和修复计划。
