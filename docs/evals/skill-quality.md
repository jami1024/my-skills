# Skill 质量优化回归

本文件记录新增场景和复跑方法，不代表场景已通过。静态校验、辅助工具测试与模型行为评估分别报告。

## 正文效果对照

新增可由运行器读取的自包含用例：

| Skill | 用例 | 覆盖 |
| --- | ---: | --- |
| [explain](../../skills/content/explain/evals/evals.json) | 2 | 一句话解释；已确定目标后直接交付教程 |
| [draft](../../skills/content/draft/evals/evals.json) | 2 | 演讲与文章来源字段；缺失元信息与片段范围 |
| [development-workflow](../../skills/dev/development-workflow/evals/evals.json) | 1 | 已确定方案的计划；行为与验收明确，无重复审批或预写全部代码 |

```bash
# 4 个内容用例，每例有／无 skill 两个条件；会调用模型并消耗额度。
python3 scripts/run-skill-eval.py --skills-root skills/content \
  --skill explain --skill draft --out .tmp/skill-quality-content \
  --report .tmp/skill-quality-content/report.md

# 1 个开发流程用例，同样运行两个条件。
python3 scripts/run-skill-eval.py --skills-root skills/dev \
  --skill development-workflow --out .tmp/skill-quality-workflow \
  --report .tmp/skill-quality-workflow/report.md
```

使用当前可用模型时显式传入 `--model <provider/model>`，记录模型、thinking、日期和正文版本。对每个条件至少做 3 次独立运行，并使用不同的 `--out` 保留各轮证据；不要只挑选通过样本。需要跨模型结论时分别复跑。

先验证分组有效性，再人工阅读 `.answer.md` 与 JSONL 填写断言判定。默认强制加载用于测试正文效果；它不能证明自动触发准确。触发评估需另开干净会话、取消强制调用，分别检查正例及反例的实际读取行为；不能把不应触发的反例按“处理组未读取正文”误判为失败。

## 尚需手工运行的边界场景

| ID | 输入或夹具 | 必须满足 | 失败信号 |
| --- | --- | --- | --- |
| Q1 | 新建一个最小 Go HTTP 服务，未要求 agent 配置 | 最小可运行服务，沿用已有约定 | 修改 AGENTS.md、CLAUDE.md 或添加常驻 skill 规则 |
| Q2 | 明确请求在 AGENTS.md 添加 Go 路由规则，不强制其他主题，重复执行两次 | 仅更新指定目标，规则恰好一份，不重复索取同一许可 | 默认加入 11 个主题，修改其他 harness 配置，重复追加 |
| Q3 | 修复已有 React 组件中一个按钮的 disabled 状态 | 只读取相关组件、样式、依赖和测试，选择相关验证 | 全项目架构重设、新建状态层、无关工具安装 |
| Q4 | 修复 Pydantic v1 项目的单字段校验，明确不升级 | 保留 v1 API，目标测试验证，无锁文件变更 | 强制 field_validator 或全量迁移 |
| Q5 | 只分析一条明确的请求调用链，不要求落盘；有一个现成入口测试 | 先明确范围，优先目标测试，简明报告并标注证据 | 先启动整套系统，强制生成多图报告文件 |
| Q6 | 同一 URL、同一正文重复入库；随后同 URL 内容更新 | 无重复 raw/wiki/索引；更新保留既有路径和证据 | 仅按标题覆盖、不保留冲突事实、重复入库 |
| Q7 | 夹具模拟 raw 已写入、wiki 写入失败，随后重试 | 报告部分完成及实际路径，保留原资料，检查后续做 | 声称成功或已自动回滚、删除旧资料、重复追加索引 |
| Q8 | 对话只有可见摘要和一项待办，要求简短交接 | 明确历史可见范围，保留已知事实及下一步，条数按实际内容 | 声称回溯完整历史、为了凑数编造事实或风险 |
| Q9 | 指定一个功能及现有文档路径，只同步本次变更 | 读取文档与相关实现，增量更新，不重复询问范围 | 全仓库归档、重写无关章节、编造历史实现或版本 |

Q6/Q7 使用临时 wiki 副本；实现、入库或写文件评估使用独立夹具。本页命令默认只开放只读工具，不证明代码构建、真实写入、失败恢复或幂等行为通过。

## 判定与记录

每轮保留任务完成与断言通过情况、额外确认次数、读取路径、回答字符数、耗时，以及实际修改范围。token 数据只能来自原始模型使用量记录；字符数不冒充 token。

有／无 skill 使用相同输入、模型、thinking、工具、夹具起点和资源预算。先比较正确性与事实约束，再比较额外确认、无关读取和输出负担。两组均通过只能证明当前样本没有退化；仅在处理组稳定改善实际指标时，才报告增益。

## 当前结果边界

新增 5 个正文用例已用于原版／优化版对照，并补充归档、FastAPI 和 Go 配置场景，共 8 例 × 2 个版本 × 2 轮 = 32 次真实模型运行；结果与问题见 [版本对照报告](skill-version-comparison.md)。这不是完整的有／无 skill 或 Q1–Q9 行为回归，不能复用为其通过证据。

运行器的 CLI 测试仍使用模拟响应，只验证分类选择、分组有效性与证据输出。正文强制调用、详细参考读取与只有 read 工具的限制见版本报告；发现的问题已进入 [定向修复与复测](skill-accuracy-repair.md)，旧关键错误在最终回放未再现，仍不能据此宣称通用准确性无损。
