# Content Draft

## 先核对节目身份

在正文开头明确以下信息；输入缺失就写 `[待补充]`，不要猜：

- 节目或播客名称；
- 嘉宾姓名与身份；
- 节目标题；
- 载体（播客、视频播客、访谈等）；
- 收听或观看入口；
- 发布日期（若来源未提供则标注缺失）。

## 成稿流程

1. 读取完整素材，区分主持人、嘉宾和旁白；无法确认说话人时不要强行归属。
2. 提取 3–7 个核心判断，每个判断写出来源依据；观点归纳和作者推演分开。
3. 设计面向公众号读者的标题、导语和小标题，保留原节目语境，不把口语逐句硬翻成书面语。
4. 正文使用中文 Markdown，段落短、观点先行、必要时保留少量原话。
5. 所有引用必须来自素材；素材没有时间戳时不生成时间戳。
6. 在确实需要视觉辅助的位置插入图片提示词，不生成图片本身。

```markdown
> 嘉宾：...
> 收听入口：...

## 一、核心判断
...

## 二、...
...

## 结语

## 信息缺口
- [待补充] ...

- 原始来源：...
```

## 图片提示词规则

每个提示词必须包含：**放置位置、画面主体、构图/风格、比例、图中文字**。默认不放复杂文字，比例根据版式选择 `16:9` 或 `3:2`。提示词描述的是视觉方案，不得加入素材没有依据的事实。

## 交付前检查

- 读者是否知道这是节目/播客，而不是会议纪要；
- 嘉宾、节目、入口和日期是否有来源；
- 核心判断是否能回到素材；
- 缺失信息是否显式标出；
- 是否只交付 Markdown，没有偷偷生成图片或虚构时间戳。
