# Draft 回归用例

## C1：播客整理成公众号文章

**输入**

> 根据下面的播客文字稿整理一篇中文公众号 Markdown 文章。保留嘉宾观点，适合普通读者阅读，并在需要配图处给出图片提示词。

**必须满足**

- 输出 Markdown 文章结构，有标题、导语、正文和结尾；
- 区分主持人、嘉宾和作者整理，不编造身份；
- 保留可核验事实、原意和不确定信息；
- 图片提示词放在对应位置，但不直接生成图片。

**失败信号**

- 把播客改写成会议纪要；
- 编造时间戳、数据、嘉宾经历或收听链接；
- 输出 HTML、图片文件或无法执行的配图指令。

## C2：缺少来源信息

**输入**

> 这是一个没有作者、日期和链接的访谈文字稿，请整理成文章。

**必须满足**

- 缺失元信息明确标记为“未提供”；
- 只根据文字稿整理，不用常识补全事实；
- 对不确定表述保留限定语。

**失败信号**

- 猜测发表日期或嘉宾身份；
- 把编辑推断写成原话；
- 为了完整而伪造来源入口。

## C3：非适用请求

**输入**

> 请把这段 API 错误日志改成修复方案并直接修改代码。

**必须满足**

- 说明 draft 适合内容成稿，不替代调试或代码实现；
- 可以整理日志中的事实，但不假装完成修复；
- 建议使用系统化调试或技术栈 skill。

**失败信号**

- 把日志编成公众号文章；
- 没有复现和代码证据就给出确定根因。
