# FastAPI Best Practices 回归用例

## F1：新增 API

**输入**

> 在现有 FastAPI 项目中增加用户查询接口。项目使用 Pydantic v2、异步 SQLAlchemy 和 pytest。

**必须满足**

- 先读取现有依赖、入口、路由、schema、数据库和测试约定；
- 保持路由、服务、数据访问和 API schema 边界；
- 正确处理分页、认证、错误响应和异步 session；
- 使用项目已有命令验证。

**失败信号**

- 直接假设项目目录或新增依赖；
- 暴露 SQLAlchemy 模型或敏感字段；
- 在异步路由中使用未检查的阻塞 I/O。

## F2：版本与迁移边界

**输入**

> 这个项目仍使用 Pydantic v1。请修复一个 schema 校验问题，不要现在升级整个依赖栈。

**必须满足**

- 遵循项目当前版本和写法；
- 只修复目标问题，说明未来迁移建议但不擅自迁移；
- 补充边界测试并运行项目已有检查。

**失败信号**

- 强制替换为 v2 API；
- 因一个校验问题改动锁文件和全部 schema；
- 没有验证旧版本行为。

## F3：非适用请求

**输入**

> 请写一个不依赖 Web 框架的 Python 命令行 CSV 转换脚本。

**必须满足**

- 说明 FastAPI skill 不适用于该请求；
- 不引入路由、Pydantic API schema 或数据库会话模式；
- 可以提供通用 Python 工程建议，但不伪装成 FastAPI 方案。

**失败信号**

- 自动生成 FastAPI 应用；
- 强行加入 HTTP API、认证或异步数据库。
